# Personal Schedule 原型流程与状态清单（供 E-182 静态原型）

版本：0.6 · 2026-11-06 · 依据 `plan-b-execution-boundary-spec.md` v0.6。v0.6 新增：Timeline 错过窗口与延迟触发态（spec 3.9.1–3.9.5）。v0.5：通知发布两区域/消息模板/双预览/发布暂停（3.8）、Timeline 时间源（3.9）、分享实时视图无版本 + 导入勾选 + 默认执行器复用（8.3–8.5）。其余同 v0.4（五类创建任务 + JIRA 托管入口占位、Tag/类型视图、统一补全）。全部数据为虚构本地样本，刷新可重置；模拟"保存/排程"不得伪装成真实发送。

## 1. 全局状态词汇表（原型 UI 采用统一措辞）

### 1.1 任务状态（任务列表/详情主状态）

| 状态 | 含义 | 用户可做的事 |
|---|---|---|
| `draft` | 草稿，未排程 | 编辑、删除 |
| `inactive` | 未启用（缺收件人/执行器/凭证/时区确认，常见于分享导入或未连 Memory） | 补全配置、启用、编辑、删除 |
| `pending_review` | 等待人工审核（自动答复/审批策略产生） | 批准、编辑、取消 |
| `active` | 已排程，等待下次运行 | 暂停、编辑、改期、删除（归档） |
| `paused` | 暂停，未来不触发 | 恢复、编辑、删除 |
| `completed` | 一次性任务已送达/执行完 | 查看、重新创建、删除 |
| `needs_attention` | 需要处理（凭据失效、unknown 待对账、执行失败） | 按指引修复、重试、跳过、取消 |
| `archived` | 已归档（删除即归档，保留历史） | 恢复、彻底清理 |

> 旧版的"迁移导入"来源与接管/回滚相关状态全部移除；不存在旧版界面。

### 1.2 运行（occurrence）状态 —— 投递与执行分开显示

- 投递态：`queued`（已排队）→ `claimed`（Runner 已领取）→ `dispatching` → `accepted`（下游已接收）→ `unknown`（发出后无回执，待对账）/ `failed`
- 执行态（帮我做/帮我问链）：`running` / `succeeded` / `failed` / `input_required`（Agent 需要补充输入）/ `cancelled`
- 送达态（AsMe/Bot 帮我发）：`sent`（记录 chatId/postId/messageId）
- 规则：**"HTTP 200 / 队列接受" ≠ "已发送" ≠ "Agent 做完" ≠ "已发布" ≠ "已通知"** —— 证据分开展示。

### 1.2.1 发布态（v0.5 新增，帮我做发布产出时）

`publish_pending（待发布）→ published（已发布）/ publish_paused（发布暂停：缺必填字段 | 校验失败 | 投递失败）/ publish_skipped（跳过本次）`

- 发布态与执行态分开展示：页面可同时显示"任务已完成"与"发布暂停/失败"。
- 发布暂停时可：仅重新生成正文 / 补写后发布 / 跳过本次发布——**均不重跑任务**。
- 证据条（帮我做）：投递 / 执行 / 发布 / 通知我。

### 1.3 追问链（帮我问）会话状态（来源：memory-service，只读投影 + 转发操作）

`pending_approval → scheduled → waiting_reply →（deferred ⇄ waiting_reply）→ resolved / no_reply / escalated / failed / cancelled`

- 事件流词汇：已发送初问、收到回复（含分类：答复/稍后/拒绝/无关/不明确）、已发第 N 次追问、已按已有答案跳过、结果已通知、已升级待人工确认。
- 操作：停止追问、继续追问（可设新上限与间隔）、重试。

### 1.4 执行器/连接状态

- 连接：`未配置 / 配置中 / 已连接 / 校验失败 / 需要重新授权`（凭据过期）
- 执行器探活（代理 memory probe）：`dns / connect / auth / ready` 四层失败要能指明第一失败层
- CLI worker：`在线（心跳中）/ 离线（心跳超时）/ 已撤销`；显示最近心跳、当前执行数、能力
- Memory 连接（帮我问/帮我做必需）：`未连接（任务保持 inactive）/ 已连接 / 校验失败`
- Multica：workspace/agent/autopilot 绑定进度
- OpenClaw：gateway / responses 两类实例的启用与探活

### 1.5 分享状态（发送方视角）

`未分享 / 已发布（含版本、导入计数）/ 已撤销 / 已过期（可选 TTL）`

### 1.6 JIRA 托管状态（v0.4 恢复；D1–D4 待定，占位词汇）

`未托管（引用展示）/ 准备托管 / 已托管（触发器已换 webhook，动作保留 JIRA）/ 不支持（JQL 模式，保持引用）/ 冲突（远端规则被他人修改，是否保留此检测待定 D3）`

> 退出托管的执行路径（D1）未定：原型仅保留"退出托管"占位入口，点击后显示"语义待定（仅停触发 / 恢复原触发器 / 不可退出）"，不演示任何执行路径。

## 2. 五类创建任务 + JIRA 托管入口（渐进式表单）

通用骨架：选类型 → 内容（富文本/变量预览）→ 对象/通道 → 时间（时区 + 下次运行与未来 3 次预览；频率可选 **Timeline**）→ 高级（重试/结束条件）→ 确认（含试运行预览）→ 保存（只排程，不发送）。

**时间步 · Timeline 频率（v0.5 新增）**：项目 → 里程碑（按钮显示当前 release 的日期）→ 前/后 N 天 → 时刻；右侧实时预览实际发送时间（如 mThor 26.4.0 · FF 11/10 · 前 2 天 → 11/08 09:30）。边界态：数据过期（警告 + 刷新按钮）、项目无数据（等待数据）、里程碑日期未定（等待日期）、本次时间已过（下个 release 有日期后重新排期）。

**Timeline 错过窗口态（v0.6）**：里程碑日期提前且发现较晚 → 运行记录标注"延迟触发（补发）"（宽限窗口内）或 needs_attention "错过窗口"（超宽限：显示新旧日期与错过时长，提供 立即发送 / 跳过本 release）；日期推迟 → 详情显示顺延后的新时间；已执行的 occurrence 在日期再变更时不重发（详情显示"本 release 已触发过"）。一句话创建支持"mThor FF 前 1 天 10:00…"。

> 创建表单五类；另有 `jira_automation` 托管类型由 JIRA 页面入口产生（4.2），不在创建表单中，但在类型视图/列表中与五类并列展示。

1. **AsMe（帮我发，以我身份）**：私聊/群组/多人、mention、附件（Drive 链接/上传，提示授权范围）；发送身份=用户授权的 RC 身份。
2. **Bot（帮我发，Bot 身份）**：同上但身份=Bot API；显示 Bot 凭据归属。
3. **AI Report**：模板选择（内置多个）/自定义 HTTP endpoint（仅管理员登记白名单）；JQL 与变量；响应提取规则；空结果策略（发送/静默）；生成与投递分开的状态。
4. **帮我问**：目标收件人（歧义解析/自问禁止）、问题+信息目标、审批策略（直接发/需审核）、追问上限与间隔、已有答案预检开关。未连 Memory 时保存为 `inactive` 并给出配置引导。
5. **帮我做（执行与投递，v0.5 修订）**：任务描述（执行指令只描述要做什么，收件人与格式在下一步）；执行器选择（Multica workspace/agent、OpenClaw 实例、CLI worker；可复用已配置的默认执行器）；read/write 模式（write 需审批）；**两个独立投递区域（可同时启用）**：
   - **运行通知 · 通知我**：默认开启，每次完成 / 仅失败 / 关闭；发给自己，无需选群；附小预览。
   - **发布任务产出 · 发送到联系人/群组**：默认关闭；开启后选对象、身份（我/Bot）、正文来源（直接发送最终产出 / 按模板生成）、空结果行为；消息预览。
   - **消息模板编辑器**（选"按模板生成"时出现）：预设（查询简报 / 漏洞通报 / 自定义）；每字段 名称 + 给执行器的说明 + 必填开关；可增删字段（可撤销）；预览实时更新。
   - **试运行（确认步）**：并排展示「发给你」与「发到群」的正文预览，默认不真实发送；可模拟"漏填必填字段"看发布暂停；可展开执行器返回结构示意（summary_for_owner / publish_fields / final_output）。未连 Memory 时保存为 `inactive` 并给出配置引导。
6. **JIRA 托管**（入口在 JIRA 页面，4.2；不在创建表单）：粘贴/选择规则 → 资格判定（nosearch + 任意间隔，含每日多次；JQL 模式 → 引用展示）→ 展示将替换的触发器与保留的动作 → 托管进度（转换中→已托管）。退出托管按 1.6 占位处理。

编辑约束的原型表现：改时间=新 revision（历史运行不受影响）；只改内容=后续 occurrence 用新内容；已发出的内容不可重写；暂停不停已开始的当次（提示到执行器侧停止）；删除=归档。

## 3. 管理界面

- 导航：**Tag 多对多分组** + **类型视图切换**（视图派生，切换不复制任务；类型视图含五类创建类型 + JIRA 托管）；任务列表扁平（无父子层级）；内置视图：全部 / 各 Tag / 类型 / 未分组；搜索/筛选（状态、类型、Tag）可叠加。
- Tag 管理：创建/重命名/改色/排序/合并/删除；删除 Tag 只解除关联不删任务；一任务多 Tag 的直观展示与增删。
- 列表行：标题、类型图标、Tag 徽标（多个）、状态、下次运行（含时区）、最近运行结果（四态证据缩略）、来源（Web 手建 / Glip / JIRA 托管 / 分享导入）。
- 详情页：计划（时间轴+未来预览）、运行历史（每次 occurrence 的投递/执行/发布/送达/通知证据，发布态与执行态分开显示）、追问链视图（1.3 状态与事件流、businessRef 跳转到 memory 视图）、来源信息。
- 连接与执行器面板：**Timeline 数据源**（v0.5 新增，各项目 release、最近刷新时间、引用任务数、手动刷新）。
- 日历/列表双视图；空态（分类型给出引导）；`inactive` 任务的全局"需要补全"角标与筛选。
- 键盘可操作：列表导航、快速创建、时间输入。

## 4. 联动入口流程（必须在原型中可体验）

### 4.1 Glip 定时发送（未配置 → 配置 → 自动续提）

点击闹钟 icon → 弹配置（Service 地址 + 登录/令牌）→ 验证成功写 Options → **自动续提原请求**（正文/收件人/时间保留，双击不建两条）→ 显示"已排程"收据；取消配置则不清正文不提交。已配置：一键提交，显示下次运行时间。**不回落任何旧链路**。

### 4.2 JIRA 托管联动（未配置 → 配置 → 自动续提；v0.4 恢复，执行路径占位）

托管按钮始终可见 → 未配 Service 弹同一配置组件 → 配置完成自动续提托管请求 → 走 §2 第 6 条的进度（转换中→已托管）；资格不符停在"不支持/引用"。**退出托管与冲突处理的执行路径未定（spec 2.2 D1/D3），原型只做占位入口与提示，不得标成已实现。**

### 4.3 通知与提醒桥

声明式表述：浏览器关闭不影响执行；桌面弹窗依赖扩展在线（提示性能力，非调度依赖）。

## 5. 异常与恢复场景（原型必须能演示）

1. 凭据失效（RC JWT/PAT/Memory key 过期）→ needs_attention + 重新授权路径。
2. 发送 unknown（发出无回执）→ 对账视图：只显示"待核实"，**不提供无提示的重复发送**；提供"标记已核实/重发一次"。
3. 执行失败/超时 → 重试（幂等下游自动可重试；非幂等展示警告）。
4. 服务重启/断线恢复 → 运行历史显示租约恢复；worker 离线 → 任务显示“等待 worker”。
5. **发布暂停（v0.5 新增，必须可演示）**：执行器漏填必填字段或校验失败/投递失败 → “任务已完成”与“发布暂停”并列展示；高亮缺失字段；**不用整份运行日志兜底发送**；操作：仅重新生成正文 / 补写后发布 / 跳过本次发布，均不重跑任务；同时收到暂停通知。
6. 时间源展示：任务详情显示“时间源：Schedule Service”（单一调度器；无旧链路接管/回滚状态）。JIRA 托管任务详情显示“到期动作：webhook POST 至 JIRA（动作留在 JIRA）”，退出路径占位。
7. **Timeline 数据过期（v0.5 新增）**：发送前刷新失败 → 本次不运行，置 needs_attention 并提醒，不用旧日期发送。

## 6. Tag 分享流程（发送方，原型必须可体验；v0.5：实时视图，无版本）

1. 选择 Tag → “分享整包” → **发布前预览**：逐任务内容全文、类型分布、计划摘要、敏感内容标注、将剥离字段清单（凭证/收件人 ID/运行历史不携带）；提示“分组后续变化会实时反映在分享中”。
2. 确认发布 → 生成分享链接（**无版本概念**，接收方看到的恒为当前 Tag 任务集）；分享管理列表显示状态（已发布/已撤销）、**导入计数**（多少人导入过）、撤销按钮。
3. 撤销 → 链接立即失效；接收方打开显示“分享已撤销”；已导入副本不受影响。
4. Tag 增删任务 → 分享页内容随之更新（演示：发布后改动分组，刷新分享链接看到最新内容）；已导入副本不变化。

## 7. 分享导入流程（接收方，原型必须可体验；v0.5：可选导入 + 默认执行器复用）

1. 打开分享链接 → **实时预览页**：任务数、类型分布、逐任务内容/计划/时区（原时区与接收方时区并列）、接收后需补全项提示；**任务勾选清单，默认全选**。
2. **已安装扩展**：页面检测到 Personal AI Extension → “一键批量导入”（按勾选集）→ 进度 → 逐任务结果（就绪可启用 / 待补全 `inactive` / 失败）。
3. **未安装扩展**：同一页面显示安装引导 + “安装完成后自动继续导入”；模拟安装完成 → 自动续入导入流程（不重复确认）。
4. **重复导入**：再次导入同一任务 → 提示已导入过并列出已导入任务；可显式选择“再次导入（创建副本）”。
5. **部分失败**：逐任务结果中失败项可单独重试。
6. **默认执行器复用（v0.5）**：导入的 Agent Task 若接收方已配置同类型执行器 → 自动绑定默认执行器，不要求补录，直接可启用（仍需收件人/时区确认）；未配置才进补全流程。导入的帮我做任务发布默认关闭。
7. 导入后：任务默认 `inactive`；可选新建“导入自 XX”Tag 并建立关联。

## 8. 统一补全入口（`inactive` → 启用）

全局"需要补全"视图聚合所有 `inactive` 任务（分享导入 + 未连 Memory）：逐任务补全收件人绑定 → 执行器选择（包内 executorTypeHint 作为建议；**已配置同类型执行器的 Agent Task 已自动复用默认执行器，不出现在补全清单的执行器项中**）→ 凭证 → 时区确认 → 校验通过 → 手动启用（支持批量）。缺任何必需项不可启用；补全入口同样覆盖"未连 Memory 的帮我问/帮我做"（Memory 连接配置引导）。

## 9. 视觉与体验要求（来自用户）

极致丝滑的创建与管理体验；界面大气美观。重点打磨：渐进式表单的节奏（每步一件事、可回退、自动保存草稿）、时间选择的下次运行即时预览、列表信息密度与层级、Tag 视图/类型视图切换的瞬时感、空态/错误态的引导语气、键盘流。响应式（桌面优先，兼顾窄窗口）。

## 10. 原型边界

- 纯静态、单 HTML 优先；无后端调用；所有状态切换用本地模拟数据与显式标注（"演示数据"）。
- 不得把模拟排程渲染成真实发送成功；涉及"发送/执行/导入"的按钮给出演示提示。
- 分享/导入全流程（§6–§8）必须可在单 HTML 内完整走通（用模拟的"扩展已安装/未安装"状态切换）。
- JIRA 托管入口（4.2、§2 第 6 条）按卡片保留在原型中；未定的执行路径（退出/冲突，spec 2.2 D1/D3）仅占位提示，不得标成已实现。
- 交付后等待用户体验决策，不自行进入生产实现（E-182 卡片约束）。
